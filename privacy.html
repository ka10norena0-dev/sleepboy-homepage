🔒 第2部：プライバシーポリシー

Sleep Boy Project（以下、「当組織」といいます。）は、本アプリにおけるユーザー情報の取扱いについて、以下のとおりプライバシーポリシーを定めます。

■ 収集する情報および利用目的

マイク音声データ（TRACKモード）
本アプリの「TRACKモード」では、ユーザーの寝息や周囲の静寂を検知し、自動で画面をロックするためにマイクを使用します。この音声データはすべて端末内（On-device）でリアルタイムに解析され、外部のサーバー等へ送信されることは一切ありません。解析後のデータは即座に破棄されます。録音・保存・外部送信はいずれも行いません。

睡眠ログおよび端末データ
本アプリが生成するすべての睡眠ログ、バッテリー残量等のデータは、端末内のローカルストレージ（SharedPreferences）にのみ保存されます。本アプリが、これらのデータを外部へ送信（テレメトリ収集）することは一切ありません。

■ IoT連携機能（ULTRAプラン）について

本アプリのULTRAプランでは、ユーザー自身が設定した以下の外部サービスと連携する機能を提供します。

  1. 連携対象サービス
    ・IFTTT（Webhook）
    ・SwitchBot API
  2. 設定情報の取扱い
    ユーザーが入力したWebhook URL、APIトークン、クライアントシークレット、デバイスID等の情報は、ユーザーの端末内にのみ保存されます。これらの情報が本アプリの開発者や第三者に送信・共有されることは一切ありません。
  3. 外部サービスへの通信について
    睡眠検知（または設定タイマー終了）のタイミングで、ユーザー自身が設定した接続先（IFTTTおよびSwitchBot社のサーバー）に対して、機器の操作を要求する通信が自動的に送信されます。この通信は本機能を実行するために必要な最小限のものであり、ユーザーが指定した接続先以外へ送信されることはありません。IoT連携機能を設定していない場合、これらの通信は一切発生しません。
  4. 第三者サービスのプライバシーポリシー
    IFTTTおよびSwitchBotとの通信・連携については、各サービス提供事業者のプライバシーポリシーが別途適用されます。開発者は、これら第三者サービスにおけるデータの取扱いについて一切の責任を負いません。
    IFTTT: https://ifttt.com/terms
    SwitchBot: https://www.switch-bot.com/pages/privacy-policy

■ フォアグラウンドサービス（FGS）の利用およびマイク権限について

本アプリは、コア機能である「睡眠および寝落ち状態のリアルタイム検知・管理機能」を提供するため、以下のフォアグラウンドサービス（FGS）およびマイク権限（RECORD_AUDIO）を使用します。

  1. 特別な用途のためのサービス（specialUse）の利用目的
    本アプリは、ユーザーが就寝・寝落ちした瞬間を正確に判定する「寝落ち検知タイマー」として動作します。画面消灯（スクリーンオフ）状態やバックグラウンド状態であっても、遅延なくリアルタイムで処理を実行する必要があるため、OSによる実行制限（WorkManagerやJobSchedulerなどの遅延可能なジョブ）では代替できません。そのため、フォアグラウンドサービス（specialUse）を利用して常駐します。
  2. マイクサービス（microphone）の利用目的
    一部の高度な監視モードにおいて、睡眠時の状態（呼吸音および周囲の動作音）の解析（音量バグの回避および音響処理）を正確に行うため、フォアグラウンドサービス中にマイク権限を使用します。
  3. データの取扱方針（プライバシー保護）
    マイクから取得される音声および音量データは、すべて端末内（ローカル環境）においてリアルタイムで解析処理され、処理終了後は即座にメモリから破棄されます。これらのデータが外部のサーバーに送信・保存されたり、第三者へ共有されたりすることは一切ありません。
  4. ユーザーによる制御
    ユーザーは端末の設定画面から、いつでもマイク権限の許可および通知（FGSの停止）を制御することができます。

■ 広告およびサードパーティ製SDKについて

本アプリには、広告表示プログラム、ならびにユーザーの行動を追跡・分析・プロファイリングするサードパーティ製SDKは一切含まれていません。

Sleep Boy Project ("we," "our," or "us") establishes this Privacy Policy to govern the handling of user information within the Application.

■ Information Collection and Use

Microphone Audio Data (TRACK Mode)
TRACK Mode uses the device microphone solely to detect ambient silence and breathing patterns for the purpose of automatic screen locking. All audio data is processed entirely on-device in real time and is never recorded, saved, or transmitted to any external server or third party. All audio data is permanently discarded immediately after processing.

Sleep Logs and Device Data
All sleep logs and battery status metrics generated by this Application are stored exclusively within the device's local storage (SharedPreferences). This Application never transmits any of this data externally. Outbound telemetry is absolute zero.

The ULTRA plan of this Application provides integration with the following external services, configured entirely by the user.

  1. Supported Services

    All information entered by the user — including Webhook URLs, API tokens, client secrets, and device IDs — is stored exclusively on the user's device. This information is never transmitted to or shared with the developer or any third party.

If the IoT integration is not configured, no such communication occurs at all.

■ Foreground Service (FGS) Usage and Microphone Permission

To deliver its core function — real-time detection and management of sleep and drift-off states — this Application uses the following Foreground Services (FGS) and the microphone permission (RECORD_AUDIO).

  1. Purpose of the Special-Use Foreground Service (specialUse)
    This Application operates as a "drift-off detection timer" that precisely determines the moment the user falls asleep. Because processing must run in real time without delay — even while the screen is off or the app is in the background — deferrable job mechanisms restricted by the OS (such as WorkManager or JobScheduler) cannot serve as substitutes. For this reason, the Application runs persistently using a Foreground Service of type specialUse.
  2. Purpose of the Microphone Foreground Service (microphone)
    In certain advanced monitoring modes, the microphone permission is used during the Foreground Service to accurately analyze sleep-state conditions (breathing sounds and ambient movement sounds), including volume-bug avoidance and acoustic processing.
  3. Data Handling Policy (Privacy Protection)
    All audio and volume data obtained from the microphone is analyzed in real time entirely on-device (locally) and is immediately discarded from memory once processing is complete. This data is never transmitted to or stored on any external server, nor shared with any third party.
  4. User Control
    Users may control microphone permission and notifications (including stopping the FGS) at any time from the device settings screen.
